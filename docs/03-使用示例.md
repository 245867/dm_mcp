# 03 · 使用示例

## 1. 命令行自检（最快确认可用性）

```bat
:: 启动即做宿主位数自检：若为 64 位，会自动查找 32 位 Python 并重新拉起自身
:: （找不到则打印“获取/配置 32 位 Python”引导并返回码 2 退出）
python run_server.py --check

:: 显式指定 32 位解释器 / 只看引导不重拉
python run_server.py --check --python32 "D:\Python311-32\python.exe"
python run_server.py --check --no-relaunch

python run_server.py --check --allow-write
python run_server.py --check --window-class UnrealWindow --window-title 剑灵 --module bnsr.exe
```

## 2. stdio（MCP 客户端）

启动时会自动完成“加载 dm → 加载盾 → 查找并绑定《剑灵》窗口”，因此客户端通常**不需要**再调 `dm_find_window` / `dm_bind_window`；先用 `dm_status` 看 `host.bits`、`guard_loaded`、`bound_hwnd`、`auto_bind` 即可。


## 3. HTTP 常驻（REST 桥）

```powershell
# 启动：python run_server.py --mode http --port 27043

# 健康检查 / 状态
Invoke-RestMethod http://127.0.0.1:27043/health
Invoke-RestMethod http://127.0.0.1:27043/status

# 默认绑定：启动时已自动执行一次；游戏后启动 / 窗口重建时再调一次即可
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:27043/api/dm_auto_bind `
  -ContentType "application/json" -Body '{"args":{}}'

# 等价的手动方式（一般不需要）
Invoke-RestMethod "http://127.0.0.1:27043/api/dm_find_window?class_name=UnrealWindow&title=剑灵"
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:27043/api/dm_bind_window `
  -ContentType "application/json" -Body '{"args":{"hwnd":"0x602F0"}}'

# 取模块基址 + 读取（64 位）
Invoke-RestMethod "http://127.0.0.1:27043/api/dm_get_module_base_addr?module_name=bnsr.exe"
Invoke-RestMethod "http://127.0.0.1:27043/api/dm_read_int?addr=0x140000000&type=0"

# MCP over HTTP（JSON-RPC）
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:27043/mcp `
  -ContentType "application/json" `
  -Body '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"dm_read_int","arguments":{"addr":"0x140000000","type":0}}}'
```

## 4. Python 客户端（零依赖，仅标准库）

```python
import json, urllib.request

def call(tool, **args):
    req = urllib.request.Request(
        "http://127.0.0.1:27043/api/" + tool,
        data=json.dumps({"args": args}).encode(),
        headers={"Content-Type": "application/json"})
    return json.loads(urllib.request.urlopen(req).read().decode("utf-8"))

print(call("dm_status"))
hwnd = call("dm_find_window", class_name="UnrealWindow", title="剑灵")["hwnd"]
call("dm_bind_window", hwnd=hwnd)
base = call("dm_get_module_base_addr", module_name="bnsr.exe")["base"]
print(hex(call("dm_read_int", addr=hex(base), type=0)["value"]))   # 0x905a4d
```

## 5. 真实读写验证（写测试只碰临时内存）

```python
# 1) 在目标进程申请 0x100 字节
addr = call("dm_virtual_alloc_ex", size=0x100, type=0, protect=0x40)["address"]
# 2) 写 8 字节并读回
call("dm_write_int", addr=hex(addr), value=0x1122334455667788, type=3)
back = call("dm_read_int", addr=hex(addr), type=3)["value"]
assert back == 0x1122334455667788
# 3) 释放
call("dm_virtual_free_ex", addr=addr, type=1, size=0x100)
```

## 7. 多级指针链的读法（第二步预告）

上层最常见的用法是「沿一条多级指针链把目标数值读出来」。MCP 侧只提供单次读，多级解引用由调用方串起来：

```
base = call("dm_get_module_base_addr", module_name="bnsr.exe")["base"]
p1   = call("dm_read_int", addr=hex(base + OFF_1), type=3)["value"]   # 解一级指针
p2   = call("dm_read_int", addr=hex(p1 + OFF_2), type=3)["value"]     # 再解一级
value = call("dm_read_int", addr=hex(p2 + OFF_3), type=3)["value"]    # 最终数值
```

要点只有三条：解指针必须 `type=3`（64 位），每一跳的地址都写成 `"0x..."` 十六进制字符串，以及模块基址用 `dm_get_module_base_addr` 取而不是写死。

至于 `OFF_1`、`OFF_2`、`OFF_3` 具体取什么值，属于上层项目的逆向结论，不在本仓库展开。MCP 只负责“把一个地址上的值稳定读出来”，偏移换成什么值都能用。
