# 02 · 工具参考与错误码

- 共 **46** 个工具；`tools/list` 返回的就是下表内容（含 JSON Schema）。
- 前置条件列含义：`loaded`=已加载 DM；`guard`=已加载 dm 盾；`target`=已绑定/指定窗口 hwnd。缺失时服务直接拒绝并返回对应错误码。
- 所有工具返回 JSON 文本；成功含 `"ok": true`，失败含 `"ok": false, "error": <错误码>`。
- 宿主约束：整个服务必须以 **32 位** Python 运行；启动时 `run_server.py` 会自动自检并（必要时）用 32 位解释器重新拉起自身。详见 [04-常见问题.md](04-常见问题.md) Q1。

## 1. 生命周期 / 状态

| 工具 | 参数 | 前置 | 说明 |
|---|---|---|---|
| `dm_load` | `dll_path?` `reg_code?` `backend?(auto/dll/com)` `guard?(默认 true)` | — | 加载 dm.dll（或创建 COM 对象）→ SetPath → Reg → Ver → 加载盾。`auto` 先 COM 后 dll 直调；盾失败时不抛错，返回 `warning` + `guard_error`。**注册码优先级**：本参数 > 环境变量 `DM_REG_CODE`/`DM_MCP_REG_CODE` > `config.json:reg_code`（见 [04-常见问题.md](04-常见问题.md) Q14） |
| `dm_auto_bind` | `window_class?(默认 UnrealWindow)` `window_title?(默认 剑灵)` `module?(默认 bnsr.exe)` `hwnd?` | loaded | ★ 自动查找并绑定《剑灵》窗口：依次尝试 显式 hwnd → `FindWindow(class,title)` → `FindWindowByProcess(module,title)` → `FindWindowByProcess(module,"")` → `FindWindow("",title)` → `FindWindow(class,"")`。**除显式 hwnd 外，每个候选命中后都会复核**（窗口类名必须完全等于 `window_class`，`GetWindowTitle` 必须包含 `window_title`），复核不通过则继续尝试下一候选 —— 避免误绑同名窗口类/标题的其他进程（实测存在「剑灵小助手」等第三方工具持有标题含"剑灵"的窗口）。命中即 `BindWindowEx` + `SetAsmHwndAsProcessId(1)`。**不抛异常**：游戏未启动时返回 `ok:false + error:DM_NO_TARGET + hint`；**未注册时**返回 `ok:false + error:DM_NOT_REGISTERED`（未注册调 `BindWindow` 会硬崩，已主动阻止），且仍会报出已找到的 `hwnd`；不阻断服务；`steps[]` 记录每个候选的尝试与复核结果 |
| `dm_status` | — | loaded | 宿主位数（`host.bits` / `host.exe` / `host.relaunched`）、后端、DM 版本、注册状态、盾状态与明细、已绑定 hwnd、**实际监听端口 `http_port`**、**目标窗口类名 `window_class`**、**启动默认绑定结果 `auto_bind`**、DM 最近错误 |
| `dm_reg` | `code` | loaded | `Reg`，返回 `reg_ok` |
| `dm_guard` | `modes?`（默认 `["memory2","b3"]`）`enable?` | loaded | 全部模式返回 1 才置已加载；失败抛 `DM_GUARD_NOT_LOADED` |
| `dm_get_last_error` | — | loaded | `GetLastError`，0 表示无错误 |
| `dm_version` | — | — | `Ver` |
| `dm_set_path` | `path` | — | `SetPath`，资源目录 |
| `dm_raw_call` | `method` `args?[]` | loaded（内存类需 guard） | 通用兜底，覆盖未封装接口 |

## 4. 内存写（前置：`guard` + `target`；**中风险**）

| 工具 | 参数 | 说明 |
|---|---|---|
| `dm_write_int` | `addr` `value` `type?(0)` `hwnd?` | `WriteInt`；type 0=4字节 1=2字节 2=1字节 3=8字节。原生签名 `(hwnd, addr, type, v)`，**type 在 value 之前** |
| `dm_write_float` | `addr` `value` `hwnd?` | `WriteFloat` |
| `dm_write_double` | `addr` `value` `hwnd?` | `WriteDouble` |
| `dm_write_string` | `addr` `value` `type?(0)` `hwnd?` | `WriteString`；原生签名 `(hwnd, addr, type, v)` |
| `dm_write_data` | `addr` `data`（hex 或 base64） `encoding?(hex)` `hwnd?` | 分块 `WriteInt` 落字节流 |

> 写接口返回体含 `"risk": "中风险：已写入目标进程内存，操作不可撤销"`。写 DM/游戏自身数据结构前请自行确认地址来源与副作用。
>
> **⚠️ 地址必须传十六进制**：所有地址参数请用 `"0x140000000"`（`dm_*` 工具层已自动归一化，
> 但如果你走 `dm_raw_call` 直调，就必须自己保证是 hex 形式）。
> 传十进制字符串时 DM **不报错、`GetLastError` 也是 0，但会静默返回 0** —— 详见
> [Q20](04-常见问题.md#q20-读内存成功但值恒为-0--最危险的一个坑)。
>
> 原生调用形态（以下签名**已用 dm.dll 自带类型库逐条核对**，见 [Q21](04-常见问题.md#q21-dm_virtual_alloc_ex--dm_virtual_free_ex-报-dm_call_failedidispatchinvoke-失败)）：
>
> ```
> ReadInt(hwnd,addr,type) · ReadFloat(hwnd,addr) · ReadDouble(hwnd,addr)
> ReadString(hwnd,addr,type,len) · ReadDataAddr(hwnd,addr,len)
> WriteInt(hwnd,addr,type,v) · WriteFloat(hwnd,addr,v) · WriteDouble(hwnd,addr,v)
> WriteString(hwnd,addr,type,v)
> VirtualAllocEx(hwnd,addr,size,type)                        ← 4 参，**无 protect**
> VirtualProtectEx(hwnd,addr,size,type,old_protect)           ← 末位是"旧属性"输出位
> VirtualFreeEx(hwnd,addr)                                   ← **仅 2 参**，无 size/type
> Reg(code,Ver)                                              ← Ver 即"附加码"
> ```
>
> 核对手法（比查任何文档都权威）：
>
> ```python
> import win32com.client
> o = win32com.client.Dispatch('dm.dmsoft')
> ti = o._oleobj_.GetTypeInfo(); ta = ti.GetTypeAttr()
> for i in range(ta.cFuncs):                    # 本版本 444 个方法
>     n = ti.GetNames(ti.GetFuncDesc(i).memid)
>     if n and n[0].lower() in ('virtualfreeex','findint','reg'):
>         print(n, len(n) - 1)
> ```

## 5. 内存搜索（前置：`guard` + `target`）

| 工具 | 参数 | 说明 |
|---|---|---|
| `dm_find_int` | `addr_range` `value_min` `value_max?`（省略=精确匹配） `type?(0)` `step?(1)` | `FindInt(hwnd,range,min,max,type)`；**本体无 `step`**，`step!=1` 时自动改用 `FindIntEx` |
| `dm_find_float` / `dm_find_double` | `addr_range` `value_min` `value_max?` `step?(1.0)` | `FindFloat` / `FindDouble`；`step!=1` 时自动走 `*Ex` |
| `dm_find_string` | `addr_range` `value` `type?(0)` `step?(1)` | `FindString(hwnd,range,value,type)` |
| `dm_find_data` | `addr_range` `data`（空格分隔 hex，支持 `??` 通配） `step?(1)` | `FindData(hwnd,range,data)` |

地址范围格式：`"0x140000000-0x150000000"`（DM 官方 `起始-结束` 形式）。
服务同时兼容 `:` / `~` 分隔与十进制写法（会自动转成 hex）。

> **⚠️ `dm_find_*` 在剑灵（ACE 保护）下返回空是预期行为，不是工具坏了。**
> 读写完全正常，但 ACE 的影子页保护让遍历扫描看不到真数据。
> 判定方法：**用同一地址的 `dm_read_int` 打对标**——读得到而搜不到，就是 ACE 限制。
> 替代方案：用已知偏移 + `dm_read_int` 沿指针链逐点读取（偏移表由上层工程自行维护）。
> 完整证据见 [docs/07](07-实机验证记录_v1.1.2.md) §5 与 [Q22](04-常见问题.md#q22-dm_find_int--dm_find_data-一直搜不到东西)。

## 8. 错误码

### 8.1 服务层错误码（dm-mcp 自有，稳定）

| 错误码 | 含义 | 常见处置 |
|---|---|---|
| `DM_MCP_NOT_32BIT` | 宿主为 64 位且未开启自动重拉（`--no-relaunch`） | 去掉 `--no-relaunch`（默认会自动重拉 32 位），或直接用 32 位 Python 启动 |
| `DM_MCP_NO_PYTHON32` | 本机未找到可用的 32 位 Python 解释器，无法自举 | 安装 32 位 Python（见 [04-常见问题.md](04-常见问题.md) Q1），或用 `--python32` / `config.json:python32_path` / 环境变量 `DM_MCP_PYTHON32` 指定 |
| `DM_MCP_RELAUNCH_FAILED` | 已找到 32 位解释器，但重新拉起自身失败 | 用 `--python32` 给出 32 位 python.exe 的**绝对路径**，并确认其可执行 |
| `DM_MCP_AUTOBIND_FAILED` | 启动默认绑定《剑灵》窗口失败 | 确认游戏已运行（class=UnrealWindow / bnsr.exe）；随后手动调用 `dm_auto_bind` 重试 |
| `DM_DLL_NOT_FOUND` | 未定位到 dm.dll | 用 `--dm-path` / 环境变量 `DM_DLL` / `config.json` 指定 |
| `DM_LOAD_FAILED` | dll 与 COM 两条后端都不可用 | 确认 dm.dll 位数与注册（`regsvr32 dm.dll` 或 DM 自带注册工具） |
| `DM_EXPORT_MISSING` | 后端中不存在该接口 | 换后端（`--backend com`）或用 `dm_status` 看导出数 |
| `DM_NOT_LOADED` | 尚未加载 | 先 `dm_load` |
| `DM_NOT_REGISTERED` | `Reg` 未成功 | 补注册码；部分盾模式与高级接口可能不可用 |
| `DM_GUARD_NOT_LOADED` | ★ 未加载 dm 盾 | 调 `dm_guard`；确认注册码与管理员权限 |
| `DM_NO_TARGET` | 未绑定窗口 | `dm_find_window` → `dm_bind_window`（或 `dm_set_target`） |
| `DM_CALL_FAILED` | DM 接口返回 0（失败） | 返回体含 `dm_return` 与 `dm_last_error` |
| `DM_INVALID_PARAM` | 参数不合法 | 对照工具 schema |
| `DM_UNKNOWN_TOOL` | 未知工具名 | 调 `tools/list` 取准确名称 |
| `DM_INTERNAL` | 服务内部异常 | 查看 `dm_mcp.log` |

失败返回示例：

```json
{"ok": false, "error": "DM_GUARD_NOT_LOADED", "message": "未加载 dm 盾（DmGuard），已拒绝该内存操作。请先调用 dm_guard",
 "detail": {"guard_modes": ["memory2","b3"], "guard_detail": [{"mode":"memory2","ret":0,"ok":false}]},
 "hint": "调用 dm_guard（默认加载 memory2 + b3 两个盾），成功返回后即可读写"}
```

### 8.2 DM 插件自身返回值 / 错误码

- DM 多数接口：**返回 0 表示失败、1 表示成功**（部分接口返回句柄或地址，语义见上表）。
- 失败原因由 `GetLastError()` 给出，**0 表示无错误**；服务在 `DM_CALL_FAILED` 中随附 `dm_last_error` 原值，不做转义或猜测。
- 建议排错顺序：`dm_get_last_error` → 检查盾状态（`dm_status`）→ 检查绑定（`dm_bind_window`）→ 检查地址表达式是否符合 CE 风格。
